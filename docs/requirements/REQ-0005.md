# REQ-0005：M1 视觉识别基础设施与 Action Guard Dry-Run

状态：Ready for Codex  
优先级：P0  
依赖：REQ-0003、REQ-0004  
前置状态：REQ-0004 已 ACCEPTED 并合入 main

## 1. 目标

建立后续角色切换、副本识别、免费次数保护和战斗策略所依赖的“看懂画面”能力。

本任务只负责：

- 高分辨率屏幕帧采集优化。
- 目标游戏 viewport / ROI 坐标体系。
- 图像模板匹配基础设施。
- OCR 基础设施。
- 页面定义与页面识别。
- 识别置信度与 UNKNOWN / AMBIGUOUS 处理。
- Action Guard 的 dry-run 骨架。
- 模板采集、裁剪、标注和本地调试工具。
- 在目标 Pad 上对若干真实游戏页面进行“只识别、不点击”的验证。

**本任务仍然禁止向游戏内容区发送真实点击、滑动、返回或副本操作。**

REQ-0005 完成后，系统应该具备：

```text
游戏画面
→ 捕获 Frame
→ 映射目标窗口/viewport
→ 提取 ROI
→ Template / OCR Signals
→ PageDetector
→ PageMatch(pageId, confidence, evidences)
→ ActionGuard.plan(...)
→ DRY_RUN / WOULD_EXECUTE
```

但最后一步必须停在 dry-run。

## 2. 为什么这一阶段单独做

REQ-0004 已解决：

- Android 工程。
- AccessibilityService。
- MediaProjection 持续采集。
- 自由窗口门禁。
- READY / WAIT_TARGET_ACTIVE / RUNNING / PAUSED 安全握手。
- Room 基础。
- Pad Inspector。

下一阶段如果直接实现副本点击，会同时引入：

- 页面识别误判。
- 坐标映射误差。
- OCR 误识别。
- 模板版本变化。
- Action Guard 设计。
- 免费次数保护。

这些风险必须先拆开。

所以 REQ-0005 的验收标准不是“能刷副本”，而是：

> **能稳定、可解释地识别真实游戏页面，并证明一个未来动作在当前上下文中“应该/不应该执行”，但不真正点击。**

## 4. 目标页面样本

在不执行游戏操作的前提下，用户可手动把游戏切到目标页面，Codex通过屏幕采集进行识别。

首批页面至少选择 3 类：

1. 游戏主界面 / 角色主界面。
2. 设置页面或角色选择相关页面。
3. 副本列表或副本详情页面。

若手动到达副本详情页面时可见“免费(1/1)”字样，应额外建立：

- 页面识别信号。
- 免费状态 OCR/模板信号。

但本任务不能点击“前往”。

如果目标游戏 UI 在当前账号状态下无法稳定到达某页面，可替换为另一稳定页面，但必须在 IMPLEMENT 报告说明原因。

## 5. Frame Pipeline 优化

REQ-0004 当前为持续全屏 RGBA ByteArray。

M1 必须解决高分辨率长期运行的分配问题。

### 5.1 UI 不订阅原始大帧

Compose UI 不得因为每一帧新的完整 `ByteArray` 而刷新。

UI 只观察轻量 metadata：

```text
frameId
timestamp
width
height
captureFps
visionFps
lastVisionDurationMs
```

原始像素只由 Vision Worker / FrameStore 消费。

### 5.2 FrameStore

建立明确接口，例如：

```kotlin
interface FrameStore {
    fun latestSnapshot(): ScreenFrameSnapshot?
}
```

允许实现：

- 单槽 latest frame。
- 小型 ring buffer。
- 可复用 buffer pool。

不要求一次完成最复杂的零拷贝，但必须显著降低“每帧整屏大对象推动 UI 刷新”的问题。

### 5.3 Vision FPS

视觉识别与屏幕采集解耦。

建议：

- Capture 可以较高频率。
- Vision 默认 2~5 FPS。
- 具体数值配置化。
- PageDetector 没必要处理每一个屏幕帧。

### 5.4 ROI 优先

禁止持续整屏 OCR。

Template 和 OCR 默认只能在 ROI 中执行。

只有调试工具允许一次性全屏分析。

## 6. Viewport 与坐标体系

必须明确以下坐标系：

```text
Screen coordinates
Window bounds
Game content viewport
Normalized viewport coordinates [0,1]
ROI coordinates
```

### 6.1 ViewportMapper

推荐接口：

```kotlin
data class NormalizedRect(
    val left: Float,
    val top: Float,
    val right: Float,
    val bottom: Float,
)

interface ViewportMapper {
    fun toScreen(rect: NormalizedRect, viewport: Rect): Rect
    fun pointToScreen(x: Float, y: Float, viewport: Rect): Point
}
```

### 6.2 禁止绝对固定屏幕坐标

任何未来模板 ROI 或动作目标均使用：

- normalized viewport 坐标。
- anchor-relative 坐标。

不能写成：

```text
x=1241, y=782
```

作为业务事实。

### 6.3 内容区与窗口装饰

联想电脑模式的窗口可能包含：

- 标题栏。
- 边框。
- 系统装饰。

必须区分：

```text
windowBounds
contentViewport
```

若 M1 无法自动精确推导 contentViewport：

- 允许通过一次本地校准建立 profile。
- profile 只保存在本机。
- 公开仓库只保存 schema / example。
- Action Guard 在 viewport 未确认时必须拒绝动作。

## 7. Template Engine

### 7.1 模板定义

模板 metadata 至少包含：

```json
{
  "id": "page.settings.title",
  "version": 1,
  "pageId": "SETTINGS",
  "roi": {
    "left": 0.0,
    "top": 0.0,
    "right": 1.0,
    "bottom": 1.0
  },
  "threshold": 0.90,
  "scalePolicy": "FIXED_OR_LIMITED",
  "negative": false,
  "asset": "..."
}
```

### 7.2 模板来源

真实游戏模板允许来源于用户本人游戏截图。

公开仓库中的模板必须经过隐私检查：

- 不含角色私密名称（若用户不希望公开）。
- 不含账号 ID。
- 不含聊天消息。
- 不含通知。
- 不含二维码。
- 不含设备或网络信息。

不适合公开的模板保存在本地私有模板目录，并通过配置引用。

### 7.3 匹配输出

```kotlin
data class TemplateMatch(
    val templateId: String,
    val confidence: Float,
    val rect: Rect,
    val timestamp: Long,
)
```

必须保留 evidence，不能只返回 true/false。

### 7.4 阈值

阈值由模板配置，不统一硬编码。

高风险页面/按钮的模板阈值应高于普通导航提示。

## 8. OCR

### 8.1 目标

M1 OCR 用于识别少量关键文本，不做“整屏读懂”。

至少支持：

- 页面标题。
- 免费次数文本，例如已观察到的“免费(1/1)”。
- 可选稳定的按钮文字。

### 8.2 OCR 输出

```kotlin
data class OcrEvidence(
    val text: String,
    val normalizedText: String,
    val confidence: Float?,
    val rect: Rect,
)
```

### 8.3 标准化

中文 OCR 至少做：

- trim。
- 全角/半角归一。
- 空白归一。
- 常见括号归一。

免费次数判断不得只用包含“免费”：

优先匹配：

```text
免费(1/1)
免费（1/1）
```

后续其他格式必须通过真实样本增加。

### 8.4 OCR 失败

OCR 失败不等于“免费已用完”。

正确行为：

```text
无法确认
→ UNKNOWN / NOT_CONFIRMED
→ 不允许消费动作
```

## 9. PageDefinition

页面由多信号组合，而不是一个模板决定。

建议 schema：

```json
{
  "pageId": "DUNGEON_DETAIL",
  "version": 1,
  "required": [
    {"type": "template", "id": "dungeon.detail.anchor"}
  ],
  "optional": [
    {"type": "ocr", "pattern": "免费"}
  ],
  "negative": [
    {"type": "template", "id": "purchase.dialog"}
  ],
  "threshold": 0.88
}
```

### Required

任何 required signal 明确失败：

- 页面不能 MATCH。

### Optional

用于增加总置信度。

### Negative

命中后应：

- 降低 confidence。
- 或直接判定其他状态。
- 消费风险模板应具有否决权。

## 10. PageDetector

输出：

```kotlin
sealed interface PageDetection {
    data class Matched(
        val pageId: String,
        val confidence: Float,
        val evidences: List<VisionEvidence>,
    ) : PageDetection

    data class Ambiguous(
        val candidates: List<PageCandidate>,
    ) : PageDetection

    data class Unknown(
        val evidences: List<VisionEvidence>,
    ) : PageDetection
}
```

### 10.1 MATCHED

必须满足：

- 最高候选达到页面阈值。
- 与第二候选有最低 margin。
- 无关键 negative signal。

### 10.2 AMBIGUOUS

例如：

```text
SETTINGS 0.91
CHARACTER_SELECT 0.89
```

若差距不足，不允许自动选择其一。

### 10.3 UNKNOWN

任何低信号情况返回 UNKNOWN。

不得用：

```text
“不知道是什么页面，所以猜主界面”
```

## 11. 稳定页面确认

单帧 MATCH 不直接成为业务事实。

建立稳定确认：

```text
最近 N 次识别
至少 M 次为同 pageId
confidence ≥ threshold
窗口 bounds 未变化
```

建议初版：

- N=3。
- M=2 或 3。
- 配置化。

输出：

```text
StablePage(pageId, confidence, observedAt)
```

## 13. 模板采集工具

新增电脑端工具，例如：

`tools/vision-sampler/`

目标：

1. 从本地私有 Pad Inspector screenshot 读取。
2. 允许输入/选择 viewport。
3. 按 normalized ROI 裁剪模板。
4. 生成模板 metadata。
5. 生成本地预览。
6. 检查输出是否包含可能的敏感区域。
7. 用户确认后才能复制到公开 `templates/`。

CLI 示例：

```bash
python3 tools/vision-sampler/vision_sampler.py crop \
  --image <private-screenshot> \
  --viewport-profile <local-profile> \
  --roi 0.70,0.80,0.95,0.95 \
  --id dungeon.detail.anchor
```

不得把 private screenshot 自动复制到 repo。

`docs/architecture/action-guard.md`

## 15. RiskLevel

M1 建立统一风险等级：

```text
SAFE
NORMAL
SENSITIVE
FORBIDDEN_AUTO
```

含义：

### SAFE

普通返回、打开无资源消耗菜单。

### NORMAL

进入普通页面、选择普通 tab。

### SENSITIVE

涉及：

- 副本次数。
- 奖励确认。
- 可能消耗游戏资源。

必须有额外 evidence。

### FORBIDDEN_AUTO

- 付费购买。
- 钻石确认。
- 现金购买。
- 未知消耗。
- 无法确认含义的按钮。

M1 所有等级最终都只 dry-run。

## 16. Free Attempt Signal

建立独立语义：

```text
AVAILABLE
EXHAUSTED
UNKNOWN
```

M1 至少需要可靠识别：

```text
AVAILABLE
UNKNOWN
```

如果没有真实“已用尽”样本：

- 不允许猜 exhausted UI。
- 保持 UNKNOWN。
- 后续通过实机样本补充。

禁止：

```text
没有识别到“免费(1/1)” = 已用完
```

## 19. 真机测试

通过无线 ADB 在 Pad 执行。

### 19.1 页面识别

用户手动打开至少 3 类目标游戏页面。

对每一页：

- 连续识别至少 10 秒。
- 记录正确率。
- 记录 confidence。
- 记录 vision FPS。
- 记录平均/95p 识别耗时。
- 检查 UNKNOWN 是否只在切页或确实不确定时出现。

### 19.2 窗口变化

在已建立 viewport profile 后：

- 移动游戏窗口。
- 缩放游戏窗口。

预期：

- WindowGate 变化。
- Vision 结果失效/暂停。
- ActionGuard dry-run DENY。
- 不继续沿用旧 ROI。

### 19.3 失焦

助手或其他窗口 active：

- targetActive=false。
- 页面可以保留“可见识别”用于调试，但 ActionGuard 必须 DENY。

### 19.4 免费状态

若能手动进入真实副本详情：

- 读取“免费(1/1)”。
- 输出 AVAILABLE。
- 生成 START_DUNGEON_FREE 的 dry-run Decision。
- **绝不执行点击。**

## 20. 性能验收

目标不是极致性能，但必须给出基线。

Codex在 IMPLEMENT 中记录：

- Pad 分辨率。
- Capture FPS。
- Vision FPS。
- 单次 template match 平均耗时。
- 单次 OCR 平均耗时。
- PageDetector 平均耗时。
- P95。
- 运行 5 分钟的内存前后差值。
- 是否出现明显连续 GC / 卡顿。

具体阈值不提前硬编码为“必须几毫秒”，先获得真实 Pad 基线。

但以下视为失败：

- Compose UI 因 vision frame 每帧整页重组而明显卡顿。
- 5 分钟内内存持续无界增长。
- 每帧整屏 OCR。
- 页面识别阻塞主线程。

## 26. Codex 不应做的事

- 不要提前实现“自动点设置”。
- 不要自动点“前往”。
- 不要自动点击角色。
- 不要加入付费流程。
- 不要因为 OCR失败猜测免费状态。
- 不要把完整真实截图提交公开仓库。
- 不要把页面识别逻辑写死在 Compose UI。
- 不要让 Vision直接调用 AccessibilityController。
- 不要为了提高“识别成功率”把 UNKNOWN 强行归类。
