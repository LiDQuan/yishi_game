# REQ-0002：公开仓库安全改造

## 背景

Gitee 仓库即将公开，需要确保当前文件、暂存内容和 Git 历史不包含真实敏感信息，并为后续提交建立可重复执行的安全检查。

## 目标

- 强化 `.gitignore`，隔离凭据、签名材料、设备数据、私有运行数据和生成物。
- 建立 `~/.config/yishijieyongzhe/` 本地敏感数据边界。
- 提供只含假值或空值的公开配置样例。
- 增加公开仓库安全扫描脚本，同时检查工作区、暂存区和完整 Git 历史。
- 在协作协议中明确公开仓库安全政策。

## 验收标准

- `python3 tools/security/check_public_repo.py --self-test` 通过。
- `python3 tools/security/check_public_repo.py --history` 通过。
- 扫描发现问题时只输出规则、文件和行号，不输出匹配值。
- Git 历史中不存在已识别的 Token、密码、私钥、签名文件、设备信息、原始日志或敏感截图。
- 本地敏感目录权限为 `700`；已有本地 env 文件权限为 `600`。
- 生成 `codex/reports/IMPLEMENT-0002.md` 和更新后的 `codex/handoff/LATEST.md`。
- 变更提交并成功推送到 Gitee。

## 限制

- 不读取或展示本地 Secret 的内容。
- 不自动重写 Git 历史；发现历史 Secret 时先报告并要求用户撤销对应凭据。
- 二进制截图必须人工复核，文本扫描不能替代人工脱敏确认。
