# REQ-0006：M2 单角色单副本真实业务闭环

状态：Ready for Codex  
优先级：P0  
依赖：REQ-0004、REQ-0005  
目标：**开始真实业务开发，不再继续扩建基础设施。**

## 1. 本轮目标

跑通第一条真正可用的业务链：

```text
当前角色
→ 进入副本入口
→ 识别目标副本
→ 打开副本详情
→ 确认“免费(1/1)”
→ 真正点击进入
→ 等待加载
→ 战斗
→ 识别胜利/失败
→ 处理奖励/返回
→ 写入 DailyExecution
```

本轮允许真实游戏点击。

先只做：

- 当前角色。
- 一个用户指定/实测可达副本。
- 一次完整闭环。
- 优先使用游戏原生自动战斗。

不要同时做多角色、多副本、复杂 Boss 技能策略。

## 2. 开发原则

从现在开始业务优先。

不再新增大规模框架、抽象层或“为了以后可能用”的防御机制。

只有以下最小安全条件必须保留：

1. 目标游戏 active。
2. WindowGate = MATCHED。
3. 当前页面已稳定识别。
4. 动作目标已识别。
5. 涉及副本次数时必须明确识别“免费(1/1)”。
6. 购买/钻石/额外次数按钮永不自动确认。
7. 每一步最多有限重试，失败就停，不死循环。

除此之外，优先跑通业务。

## 3. 首个真实 Action Executor

实现真正的 Action Executor：

```text
ActionIntent
→ ActionPolicy
→ ActionGuard
→ ALLOW
→ AccessibilityController.tap()
→ 等待页面变化
→ 验证 postcondition
```

要求：

- 所有真实点击仍从 Action Guard 进入。
- 不允许业务模块直接调用 tap/swipe。
- 只实现本轮需要的少量动作。

首批动作建议：

```text
OPEN_DUNGEON
SELECT_DUNGEON
START_DUNGEON_FREE
CONFIRM_REWARD_OR_RETURN
```

实际名称可按真实 UI 调整。

## 4. 不再要求“完美按钮框”

REQ-0005 已经证明 OCR boundingBox 可用。

本轮允许：

- OCR 文字 boundingBox 中心点击。
- 经人工确认的 template target。
- Accessibility node bounds。

优先使用最稳定的一种。

不要因为“按钮框还不够完美”继续停留在基础设施阶段。

## 5. 副本页面采样

Codex 使用无线 ADB 配合用户手动操作，采集以下真实页面：

1. 副本入口/列表。
2. 目标副本卡片。
3. 副本详情。
4. “免费(1/1)”状态。
5. 进入/前往按钮。
6. 加载页。
7. 战斗页。
8. 胜利页。
9. 失败页。
10. 奖励/返回页。

若某页面无法一次采齐，边做边补。

不要等待“所有页面素材齐全”才开始写业务。

具体名称以真机实测为准，不猜。

## 8. 免费次数规则

这是本轮唯一必须严格保留的业务保护。

只有同时满足：

```text
DailyExecution 今日未 SUCCESS
+
当前稳定页 = DUNGEON_DETAIL
+
FreeAttemptState = AVAILABLE
+
未检测到购买/钻石/额外次数确认
+
开始按钮目标已确认
```

才允许执行：

```text
START_DUNGEON_FREE
```

任何一个条件 UNKNOWN：

```text
停止该副本流程
→ 记录原因
→ 不点击
```

本轮不要求识别所有“免费已用完”的 UI 变体。

看不到明确免费状态就不进。

## 9. 原生自动战斗优先

本轮不做脚本技能释放。

进入战斗后：

1. 检测是否已经开启游戏原生自动战斗。
2. 如果需要点击一次“自动”，允许增加一个真实动作。
3. 然后等待战斗结果。
4. 每隔合理时间检查一次：
   - 胜利。
   - 失败。
   - 仍在战斗。
   - 异常/未知。

不要对技能栏逐技能操作。


```text

→ 不继续乱点
```

## 11. 结果识别

至少识别：

```text
VICTORY
FAILURE
UNKNOWN
```

胜利后：

- 处理奖励页或返回。
- 验证已回到安全页面。
- 写 DailyExecution SUCCESS。

失败：

- 写 FAILED。
- 本轮默认不自动重打。
- 停止流程。

UNKNOWN：

- 等待有限时间。
- 超时后失败退出。

## 20. 地图分组与副本遍历（新增业务规则）

游戏副本不是一个扁平列表，而是按等级区间分布在不同地图中，例如：

```text
地图A：0~50级
  ├─ 副本A1
  ├─ 副本A2
  └─ 副本A3

地图B：50~100级
  ├─ 副本B1
  ├─ 副本B2
  └─ 副本B3

后续还有更高等级地图。
```

具体地图名称、精确等级区间和副本清单必须以真机实际 UI 为准，不在代码中猜测。

### 20.1 业务模型

副本必须隶属于地图：

```text
MapGroup
- mapId
- mapName
- levelMin
- levelMax
- sortOrder
- dungeons[]

Dungeon
- dungeonId
- dungeonName
- mapId
- sortOrder
```

角色执行计划按“已解锁/需要刷的地图”组织，而不是直接遍历全局副本列表。

### 20.2 主循环

单角色完整副本流程改为：

```text
进入副本系统
↓
获取/加载该角色需要刷的地图列表
↓
for 每张地图：
    当前是不是目标地图？
    ├─ 是 → 继续
    └─ 否 → 打开地图切换 → 选择目标地图 → 验证地图名称/锚点
          ↓
    遍历该地图中的副本
          ↓
    for 每个副本：
        今日已 SUCCESS？
        ├─ 是 → 跳过
        └─ 否
            ↓
          打开副本详情
            ↓
          明确识别 免费(1/1)？
            ├─ 是 → 进入并完成副本
            └─ 否 → 跳过该副本
          ↓
        回到当前地图的副本列表
↓
该地图全部处理完
↓
切下一张地图
↓
所有地图完成
↓
当前角色完成
```

### 20.3 地图切换状态

本轮新增最少业务状态：

```text
MAP_CHECK
MAP_SWITCH
MAP_VERIFY
DUNGEON_LIST
DUNGEON_DETAIL
```

地图切换的成功条件必须是：

```text
目标地图名称/唯一视觉锚点已确认
+
对应副本列表已出现
```

不要仅以“点击了地图按钮”视为成功。

### 20.4 地图解锁规则

不要仅根据等级数字硬编码推断可刷地图。

优先级：

1. 真机 UI 中可见/可选择的地图。
2. 本地配置明确启用的地图。
3. 角色等级区间仅作为辅助筛选条件。

如果某张地图不可见、未解锁或无法识别：

```text
记录 MAP_UNAVAILABLE
→ 跳过该地图
→ 继续下一张
```

不要在地图切换失败时反复无限点击。

### 20.5 REQ-0006 的实现范围调整

REQ-0006 仍然优先跑通最小真实闭环，但代码结构必须从一开始支持：

```text
单角色
→ 多地图
→ 每地图多个副本
```

Codex可以先用“1张地图 + 1个副本”完成首次真机跑通，再立即扩展为“同一角色遍历配置中的多地图/多副本”，不要另起一套架构。

### 20.6 DailyExecution

DailyExecution 的业务键继续按：

```text
gameDayKey + roleId + dungeonId
```

地图本身不作为“已完成”的最终判定键；地图只是副本的分组和导航上下文。

可以额外记录：

```text
mapId
```

用于诊断“在哪张地图刷的”，但同一副本是否完成仍以 dungeonId 为准。

### 20.7 UI

业务界面增加：

```text
当前角色
当前地图
地图进度：2 / N
当前副本
副本进度：3 / M
当前业务状态
```

最终用户看到的进度类似：

```text
角色A
地图：50~100级区域（2/4）
副本：副本B2（2/3）
状态：战斗中
```

### 20.8 首轮真机验收补充

除了单副本闭环，还需要至少验证一次：

```text

→ 切换到地图B
→ 确认地图B
→ 选择地图B中的一个副本
```

这一步必须真实发生，证明“地图层”不是硬编码假流程。

# 21. 基于真实截图与视频确认的最终业务流程（2026-09-21）

以下规则来自用户提供的 T01~T09 完整 Pad 截图及真机视频，优先级高于本文件前文中的推测性流程。

## 21.1 实际入口与区域结构

T01 主界面顶部存在副本入口，点击后进入区域地图。

实际流程：

```text
T01 游戏主界面
→ 点击顶部副本入口
→ T02 当前区域地图
→ 如需切图，点击“切换区域”
→ T03 区域选择列表
→ 选择目标区域
→ T04 目标区域地图
→ 点击右下角“地下城”
→ T06 当前区域地下城列表
```

当前截图中已确认的区域/等级区间包括：

```text
东部大陆      Lv.1  - Lv.60
虚空领域      Lv.60 - Lv.100
冰封大陆      Lv.100 - Lv.150
元素之地      Lv.150 - Lv.200
迷雾大陆      Lv.200 - Lv.250
暗影大陆      Lv.250 - Lv.300
军团领域      Lv.300 - Lv.350
风暴群岛      Lv.350 - Lv.400
亡灵之地      Lv.400 - Lv.445
```

这些区域名和等级区间可作为初始配置，但程序仍以实际 UI 可见内容为准。

## 21.2 地下城免费次数判断

不得再把免费次数写死为：

```text
免费(1/1)
```

真实 UI 中可能出现：

```text
免费(2/2)
免费(1/1)
其他 n/m
```

因此 FreeAttemptState 应基于：

```text
免费(current/total)
```

只要：

```text
current > 0
```

即可判定 AVAILABLE。

```text
current == 0
```

判定 EXHAUSTED。

无法可靠识别则 UNKNOWN。

另外，T06 地下城列表中每个副本右上角存在小数字标记时，表示该副本当前仍有免费次数；无数字标记则没有免费次数。

所以副本筛选分两级：

```text
第一层：T06 列表角标
    有免费角标 → 候选副本
    无角标 → 跳过

第二层：进入 T07 详情页后再次读取 免费(n/m)
    current > 0 → 允许进入
    current == 0 / UNKNOWN → 不进入
```

T06 角标只用于快速筛选，T07 详情页的 免费(n/m) 是最终进入依据。

## 21.3 副本进入

真实流程：

```text
T06 地下城列表
→ 点击某个有免费次数的副本
→ T07 副本进入页
→ 识别副本名称
→ 识别 免费(n/m)
→ 点击“前往”
→ 进入副本
```

进入副本后不会先出现奖励页或额外确认页。

## 21.4 副本进度是胜负判定核心

进入副本后，画面顶部存在：

```text
current / total
```

例如：

```text
0/5
1/5
...
5/5
```

或者：

```text
0/4
...
4/4
```

total 并非固定为 5。

业务定义：

```text
current == total
→ 副本已完整通关
→ SUCCESS

副本结束/退出时 current < total
→ FAILURE
```

因此不要再依赖：

- “胜利”弹窗。
- “失败”弹窗。
- 奖励结算页。

当前阶段的核心胜负依据是**副本进度是否完整达到 total/total**。

## 21.5 通关后的实际返回行为

副本完整通关后，游戏会自动返回：

```text
T01 游戏主界面
```

不会返回：

- 当前地下城列表。
- 当前区域地图。
- 奖励页面。

因此每刷完一个副本后，如果还要继续刷下一个副本，必须重新执行：

```text
T01
→ 副本入口
→ 当前/目标区域地图
→ 地下城
→ 下一个副本
```

不要假设可以在地下城列表中连续点下一个副本。

## 21.6 奖励处理

副本掉落物会自动被人物吸收。

没有：

- 奖励弹窗。
- 领取按钮。
- 确认按钮。
- 返回奖励页。

因此删除/取消本轮以下业务步骤：

```text
REWARD
CONFIRM_REWARD
CLAIM_REWARD
```

DailyExecution SUCCESS 可以在：

```text
已确认 progress == total/total
+
已返回 T01
```

后写入。

## 21.7 自动战斗真实规则

战斗画面中间存在一个自动战斗图标。

真实规则：

```text
存在该图标
→ 该副本支持游戏原生自动战斗

图标亮起
→ 自动战斗已开启

图标存在但未亮
→ 自动战斗未开启
→ 可以点击一次开启

完全没有该图标
→ 该副本不支持原生自动战斗
→ 需要手动战斗逻辑
```

REQ-0006 第一版只处理：

```text
支持原生自动战斗的副本
```

如果自动战斗图标不存在：

```text
记录 MANUAL_BATTLE_REQUIRED
→ 停止/跳过该副本
→ 不尝试技能乱点
```

手动技能战斗留给后续需求。

## 21.8 真实单副本闭环

第一版最终业务闭环应修改为：

```text
T01 主界面
↓
点击副本入口
↓
确认当前区域
↓
必要时切换区域
↓
点击右下角“地下城”
↓
T06 地下城列表
↓
根据右上角免费次数角标筛选候选副本
↓
打开候选副本
↓
T07 详情页读取 免费(n/m)
↓
current > 0？
├─ 否 → 返回/跳过
└─ 是
    ↓
  点击“前往”
    ↓
  进入副本
    ↓
  读取 progress current/total
    ↓
  检查自动战斗图标
    ├─ 存在且已亮 → 等待
    ├─ 存在但未亮 → 点击开启 → 等待
    └─ 不存在 → MANUAL_BATTLE_REQUIRED → 本轮跳过
    ↓
  持续观察副本进度
    ↓
  current == total
    ↓
  等待游戏自动返回 T01
    ↓
  写 DailyExecution SUCCESS
```

如果离开副本并返回 T01 时：

```text
current < total
```

则记录：

```text
FAILED / DUNGEON_INCOMPLETE
```

## 21.9 多副本循环必须重新进入副本系统

由于每个副本结束都会回 T01，因此同一角色刷多个副本时：

```text
for 每个副本：
    T01
    → 副本入口
    → 切/确认区域
    → 地下城
    → 副本
    → 战斗
    → T01
```

而不是：

## 21.11 本轮真机验收修订

必须至少验证：

1. T01 → 副本入口。
2. 切换一次真实区域。
3. 点击“地下城”进入当前区域地下城列表。
4. 根据 T06 角标找到一个仍有免费次数的副本。
5. T07 正确读取 免费(n/m)。
6. 点击前往并真实进入副本。
7. 正确识别副本 progress current/total。
8. 自动战斗图标存在时：
   - 已亮不重复点击。
   - 未亮只点击一次开启。
9. progress 达到 total/total。
10. 游戏自动返回 T01。
11. DailyExecution 写入 SUCCESS。
12. 同日再次执行该副本时跳过。
13. 若自动战斗图标不存在，第一版不得进入技能乱点模式。
