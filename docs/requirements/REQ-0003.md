# REQ-0003：异世界勇者自动化助手总体产品需求

状态：Approved for implementation planning  
优先级：P0  
目标平台：Android 平板  
首要目标设备：联想小新 Pad Pro 12.7  
UI 语言：中文

## 1. 背景与目标

用户需要一个可安装在 Android 平板上的图形化 APK，用于减少《异世界勇者》中重复、机械的角色轮询、副本挑战和日常任务操作。

本项目不能实现为简单的固定坐标连点器。目标是建立一个具有页面识别、状态管理、安全保护、断点续跑、日志诊断和可扩展策略系统的自动化助手。

核心目标：

1. 自动轮询多个角色。
2. 对每个角色按配置执行目标副本。
3. 每日免费挑战必须优先且只能在明确识别到“免费”状态时执行。
4. 自动完成可配置的日常任务流程。
5. 新版本优先使用游戏自带自动施法；旧版本或未解锁自动施法时支持脚本技能释放。
6. 脚本技能释放基于图像识别、状态识别和攻略规则，而不是无脑连点。
7. 记录角色、任务、副本的执行时间、次数、结果、错误和恢复过程。
8. 支持断点续跑。
9. 支持联想电脑模式下游戏自由窗口的检测和标准化。
10. 提供可诊断、可维护、可逐步扩展的工程结构。

## 2. 明确不做

第一阶段及总体设计均禁止：

- 修改游戏 APK。
- 注入游戏进程。
- 读取或修改游戏内存。
- 绕过反作弊、完整性校验或系统安全机制。
- 自动确认真实货币、钻石、付费次数或其他未知资源消耗。
- 在无法识别当前页面时继续盲点。
- 将真实 Token、账号、设备标识或原始隐私日志提交公开仓库。

## 3. 用户体验目标

用户最终希望达到：

```text
打开助手
→ 一键开始
→ 检查权限与环境
→ 检查/恢复游戏标准窗口
→ 识别当前游戏状态
→ 自动轮询角色
→ 执行该角色目标免费副本
→ 必要时执行战斗策略
→ 执行该角色/账号日常任务
→ 记录结果
→ 切换下一角色
→ 全部完成后生成日报
→ 安全停止
```

任何不确定状态必须优先暂停、重新识别或请求人工接管，而不是继续点击。

## 4. 功能需求

### FR-01 图形界面

APK 必须提供平板友好的中文 GUI。

首页至少显示：

- 自动化状态：空闲 / 初始化 / 运行 / 暂停 / 错误 / 完成。
- 当前角色。
- 当前副本或任务。
- 今日进度。
- 今日成功/失败统计。
- 最近错误。
- 开始、暂停、继续、停止。
- 跳过当前任务。
- 诊断入口。

后续页面至少包括：

- 角色管理。
- 副本计划。
- 日常任务配置。
- 战斗策略。
- 运行历史。
- 识别模板/配置版本。
- 设置与诊断。

### FR-02 运行环境检查

每次自动化开始前必须检查：

- AccessibilityService 是否启用。
- 屏幕捕获能力是否可用。
- 目标游戏是否存在/可识别。
- 当前屏幕与方向。
- 游戏窗口是否可识别。
- 当前状态是否允许开始自动化。

任何关键前置条件失败都不得开始点击。

### FR-03 游戏窗口标准化

目标设备支持电脑模式和自由窗口。

系统必须：

1. 检测目标游戏窗口的内容区域和边界。
2. 将其与已保存的标准窗口配置比较。
3. 若设备/系统允许，通过 Accessibility 或窗口 UI 操作尝试恢复到标准大小和位置。
4. 调整后重新验证。
5. 运行过程中监控窗口变化。

重要限制：

Android 普通应用不保证拥有直接调整其他 App 自由窗口尺寸的系统 API。因此实现必须分为：

- 自动标准化：设备实测可行时启用。
- 安全降级：无法自动 resize 时暂停，并明确提示用户恢复标准窗口。
- 绝不因为 resize 失败继续按旧坐标执行。

所有点击位置采用游戏内容区域的相对坐标或识别目标中心，不允许只依赖固定屏幕绝对坐标。

### FR-04 页面识别

页面识别优先级：

1. 图像模板匹配。
2. OCR / 文本识别。
3. 相对坐标与布局特征作为辅助。
4. 不允许只依赖时间延迟判断页面。

每个页面识别必须输出：

- pageId
- confidence
- 命中的关键视觉证据
- 时间戳

低于阈值必须进入 UNKNOWN / RECOVERY，不执行危险点击。

### FR-05 安全点击协议

所有自动点击统一经过 Action Guard：

1. 验证当前页面。
2. 验证目标按钮存在。
3. 验证按钮状态。
4. 检查是否属于资源消费风险区域。
5. 点击。
6. 等待并验证预期页面变化。
7. 超时则有限重试。
8. 重试仍失败则停止当前步骤并记录错误。

禁止业务模块绕过 Action Guard 直接任意点击。

### FR-06 角色管理与轮询

角色配置至少支持：

- id
- 显示名称/别名
- 职业
- 等级（可选）
- 是否启用
- 排序
- 是否启用游戏原生自动施法
- 战斗策略 id
- 副本计划
- 日常任务计划

已确认角色切换路径：

```text
游戏主界面
→ 设置
→ 返回角色选择界面
→ 角色选择
→ 选择目标角色
→ 进入游戏
→ 等待加载
→ 验证新角色
```

角色身份不能只靠点击位置确认，应尽量组合职业图标、文字/OCR、等级或稳定 UI 特征。

### FR-07 副本计划

副本必须配置化，不写死在代码。

每个角色可：

- 使用默认副本列表。
- 覆盖为自己的副本列表。
- 启用/停用某个副本。
- 配置执行顺序。

### FR-08 免费次数保护

这是 P0 安全需求。

已观察到的有效状态包括“免费(1/1)”。

执行副本前必须同时满足：

1. 本地数据库判断今日该角色该副本尚未成功消耗免费机会。
2. 当前画面明确识别到免费可用状态。
3. 当前前往/挑战按钮不是购买、钻石、付费或未知消耗行为。

若免费状态不可确认：

```text
SKIP / PAUSE
而不是点击
```

后续采集“免费用尽”“购买次数”等画面后加入消费黑名单模板。

### FR-09 副本完整闭环

副本状态至少包含：

- 进入副本选择。
- 打开副本详情。
- 免费状态确认。
- 前往。
- 加载。
- 战斗中。
- 胜利。
- 失败。
- 奖励。
- 返回。

不得仅通过固定等待时长判断胜利。

### FR-10 战斗双模式

支持三种用户设置：

- 自动判断。
- 强制游戏原生自动施法。
- 强制脚本施法。

自动判断模式：

```text
检测到游戏自动施法已启用且有效
→ NATIVE_AUTO

否则
→ SCRIPT_CAST
```

### FR-11 脚本技能释放

脚本施法至少需要识别：

- 技能 READY / CD 状态。
- 玩家血量区域。
- 可配置 Boss 机制提示。
- 可配置 Buff / Debuff。
- 可配置 Boss 阶段/血量（数据可获得时）。

第一阶段策略支持：

- 技能优先级。
- READY 即释放。
- 血量阈值触发治疗/减伤。
- Boss 读条/特定视觉模板触发打断。
- 指定阶段保留或释放爆发。

关键规则必须设置 confidence threshold；低置信度不得消耗关键技能。

### FR-12 攻略规则引擎

攻略不得直接写成硬编码 if/else 散落在 UI 自动化代码中。

应使用版本化策略配置，例如：

```json
{
  "strategyId": "warrior_xxx_v1",
  "rules": [
    {
      "priority": 100,
      "when": ["boss.cast == interruptible", "skill.interrupt.ready == true"],
      "action": "cast:interrupt"
    }
  ]
}
```

具体 DSL 可由 Codex在架构约束内细化，但必须：

- 可版本化。
- 可验证 schema。
- 可记录触发规则 id。
- 可远程/本地替换而不重写核心引擎。

### FR-13 自动日常任务

任务系统必须配置化。

每个任务由：

- 入口页面
- 前置条件
- 操作步骤
- 成功条件
- 跳过条件
- 超时
- 重试
- 风险级别

组成。

首批具体日常任务将在后续实机录制后形成独立 REQ，不在本需求中虚构按钮和路径。

### FR-14 任务流程学习/采集辅助

开发工具应支持采集：

- 点击前截图。
- 点击坐标。
- 点击后截图。
- UI dump（若有价值）。
- 当前前台 App。
- 时间间隔。

用于把用户真人操作转换为后续正式任务模板。

第一版不要求自动学习生成可运行任务，但数据格式应允许后续实现。

### FR-15 本地持久化

使用本地数据库持久化：

- 角色。
- 副本。
- 角色副本计划。
- 任务定义/绑定。
- 每日执行记录。
- 战斗策略引用。
- 错误事件。
- 同步状态。
- 应用设置。

应用被杀死或崩溃后必须能恢复到“已知安全节点”，不得默认从头重复所有已成功任务。

### FR-16 每日幂等

至少使用：

```text
date + roleId + actionType + targetId
```

形成每日执行键。

同一天同一角色同一免费副本已成功后，不得因为 App 重启再次自动消耗额外次数。

### FR-17 日志与历史

每次执行至少记录：

- 时间。
- 角色。
- 任务/副本。
- 状态机节点。
- 尝试次数。
- 结果。
- 耗时。
- 错误代码。
- 失败原因。
- 恢复动作。

战斗模式可记录关键规则触发和技能释放事件，但应控制日志体积。

### FR-18 错误现场

出现不可恢复异常时：

1. 停止后续自动点击。
2. 生成 Error ID。
3. 保存状态机上下文。
4. 保存最近有限条事件。
5. 可选保存本地错误截图。
6. 进入 ERROR / WAIT_USER。

原始截图和完整日志默认留在本地私有目录。

### FR-19 远程诊断

公开代码仓库不得接收原始诊断数据。

远程诊断分两层：

- 公开仓库：只允许脱敏错误摘要、需求、Review、策略和公共数据。
- 私有诊断通道：后续可选独立私有 GitHub 仓库或 Mac 本地中转。

任何 GitHub Token 都不得硬编码 APK。

### FR-20 技能资料采集器

电脑端工具负责：

- 搜集公开职业技能资料。
- 标记来源 URL。
- 标记游戏版本。
- 标准化技能名称、类型、效果、CD、资源、标签。
- 冲突检测。
- 人工复核队列。

输出到 `data/skills/` 的公开结构化数据。

### FR-21 Boss / 攻略资料

输出到：

- `data/bosses/`
- `strategies/`

任何来自攻略的结论必须保留来源和适用版本，避免旧版本机制污染当前策略。

## 5. 非功能需求

### NFR-01 安全优先

未知页面、低置信度、窗口变化、资源消费风险时必须停止或跳过。

### NFR-02 可维护性

游戏 UI 更新后，应优先替换模板/配置，不应要求重写整个 APK。

### NFR-03 可观察性

每个状态转换和关键动作都必须能够通过结构化日志追踪。

### NFR-04 性能

屏幕识别使用 ROI，避免每帧整屏 OCR。OCR 只作为需要文本判断时的辅助。

### NFR-05 离线优先

核心自动化不得依赖云端 AI 实时决策。战斗策略在设备本地执行。

### NFR-06 平板优先

助手 UI 针对大屏/电脑模式设计，但不得假设游戏窗口一定横屏；游戏内容区以实际检测结果为准。

### NFR-07 版本化

模板、攻略、技能数据、状态机配置和策略都必须有版本字段。

## 6. 建议技术栈

由 Codex在实际工程初始化时确认最终版本：

- Kotlin
- Jetpack Compose
- Coroutines / Flow
- Room
- AccessibilityService
- MediaProjection
- OpenCV：模板/图像匹配
- ML Kit 或等价离线 OCR：文字识别
- Kotlin Serialization / JSON schema 风格校验

ADB 只用于开发、采集和真机诊断，不作为 APK 正常运行的必需依赖。

## 9. 当前仍需通过实机补齐的数据

这些不是阻塞 M0 的前置条件：

- 小新 Pad 电脑模式下游戏窗口真实 bounds。
- 游戏包名。
- 免费次数用尽后的完整页面。
- 副本胜利/失败/奖励完整闭环。
- 角色列表完整结构。
- 关闭原生自动施法后的完整手动战斗。
- 首批日常任务真人操作流程。

Codex应利用现有无线 ADB 在后续任务中采集，不应要求用户重复手写已有可采信息。

## 10. 总体验收

最终产品至少应达到：

- 一键启动后能安全执行配置的角色/副本流程。
- 不能确认免费状态时绝不消费额外资源。
- 窗口变化时立即停止危险点击。
- 中断后可以从安全状态恢复。
- 所有关键结果可查询。
- 新增副本/任务/战斗策略主要通过配置和模板扩展。
